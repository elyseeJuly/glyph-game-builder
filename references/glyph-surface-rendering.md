# 字符表面：材质、受光与遮挡

按需阅读：已有可辨认的字符场景，需要进一步表现表面质感或空间关系时使用。本参考补充 scene-composition.md 与 glyph-spec.md，不要求简单网格游戏采用表面渲染器，也不规定引擎。

## 笔触服务形体

先保留主体轮廓、负空间与状态线索，再定义少量可复用材质。非像素块方向优先用笔画的走向、间距、重复和断裂表达表面，不以方块填充或盲文点阵密度为主要升级手段。

| 材质 | 可选笔触语法 | 保留的结构信息 |
|---|---|---|
| 金属 | `─ │ / \\` 接缝与定向划痕，稀疏铆点 | 划痕沿表面走向，接缝与外轮廓分开 |
| 玻璃 | 双边缘、少量反光、内部留白 | 留白不自动代表可以看穿的孔洞 |
| 织物 | 重复 `: / \\`，边缘松散 | 与金属的规则长线形成差异 |
| 裂口 | 接缝中断、错位、局部负空间 | 状态停止动画后仍可读 |

字形的方向、覆盖率和实际显示宽度取决于字体。暗底上更密的亮色笔触通常更亮，亮底上的深色笔触则相反；不能机械规定“越密越暗”。需要自动选字时，测量目标字体的字形覆盖率和方向，并保留手工轮廓、语义符号的优先级。

## 受光与遮挡分别处理

可以先手工标注受光、转折、背光三档；局部灯可按字符坐标计算距离衰减，修正字格高宽比，再量化为少量明暗等级。将其称为风格化近似，不把行号分区描述为法线光照或物理模拟。发光仅表现光源本身；周围物体的受光需另行定义。

前景透明文字的 z-index 不能遮住字间的背景星星。需要遮挡时，另建物体占据范围：例如与字行对齐的不透明区间，轮廓外保持透明。开放支架、真实孔洞和分离部件应明确保留空隙；不要把每行首尾字符之间一律填实。遮罩随物体一起运动，不能覆盖交互控件。

## 稳定性与尺寸

纹理保存在物体局部坐标中；随机分布使用稳定种子。连续受光转换为字符时，可用阈值滞回减少反复换字。旋转允许可见面与遮挡关系变化，但应来自一致的姿态或手工关键帧，避免把整幅平面文字旋转冒充立体转动。

窄屏优先移除细划痕和非必要注释，保留轮廓、至少一组材质特征及所有状态线索；必要时提供单独的简化构图。隐藏字符时保留占位，避免后续列错位。不要为凑下高密度画面无限缩小字号。没有连续着色需求时，静态分组 span 与现有 CSS 动画通常足够，不必引入每帧计算。

## 最小记录示例

以下是设计记录，不是必须实现的 API：

```yaml
surface:
  glyph_palette: ["─", "│", "/", "\\", ":", "·"]
  material_regions: "手工标注的金属、玻璃、织物区域"
  shading: "三档手工受光 + 可选局部灯距离衰减"
  occupancy: "实心物体区间；开放结构与孔洞显式排除"
  state_binding: "已有船况 → 连续接缝 / 交叉修补 / 断裂"
  texture_coordinates: object-local
  small_viewport: "保留轮廓、粗纹理和状态，隐藏细纹理但保留字格"
```

## 验证与判断

在真实入口检查场景，而不仅是组件画廊。隐藏解释性标签后观察主体类别；转为灰度（保留亮度差）检查材质与状态；在手机与宽屏检查字格、轮廓和触控控件；减少动态后检查静态线索。至少对比一个真实状态变化，确认没有靠颜色或瞬间动画单独承载信息。透明孔洞与实心表面应分别观察背景穿透是否符合意图。

自动测试适合确认状态、尺寸不变量和稳定输出；截图审阅适合检查造型与遮挡。两者都不能代替普通玩家的首次识别测试。记录未验证设备、动效与性能，不把文档自身视为验收证据。

## 研究依据

[Structure-based ASCII Art](https://research.cuhk.edu.hk/en/publications/structure-based-ascii-art-2/) 提供结构与字形匹配的研究方向；[Real-Time Hatching](https://gfx.cs.princeton.edu/proj/hatching/) 提供方向性笔触及跨尺度、跨明暗一致性的思路。这里借鉴原则，并非复现论文算法，也不要求输入图片或三维资产。
